# 邮件批量发送系统 — 需求文档

> 版本：v1.0  
> 日期：2026-07-06

---

## 1. 项目概述

### 1.1 背景

企业需要向多个客户批量发送内容一致的邮件，仅开头的客户称呼不同。当前缺乏统一工具，手动逐封编辑发送效率低下，且难以管理客户信息和发送记录。

### 1.2 目标

构建一个 Web 系统，实现：

1. 可视化编辑邮件正文（模板化）
2. 从通讯录中选择客户，自动填充个性化称呼
3. 通过腾讯企业邮箱 SMTP 批量发送
4. 管理客户信息与发送历史

### 1.3 目标用户

企业内部运营/销售人员，具备基本电脑操作能力。

## 2. 功能需求

### 2.1 用户认证

| 编号 | 功能 | 说明 |
|------|------|------|
| AU-01 | 登录 | 用户名密码登录，Session/JWT 鉴权 |
| AU-02 | 权限 | 区分管理员（全功能）和普通用户（发送+查看自己记录） |

### 2.2 通讯录管理

| 编号 | 功能 | 说明 |
|------|------|------|
| CT-01 | 客户列表 | 分页展示客户，支持按姓名/邮箱/称呼搜索 |
| CT-02 | 新增客户 | 填写：姓名、称呼（如"张总""李老师"）、邮箱地址，必填校验 |
| CT-03 | 编辑客户 | 修改客户信息 |
| CT-04 | 删除客户 | 二次确认后删除 |
| CT-05 | 批量导入 | 支持 CSV/Excel 导入客户，含格式校验与重复检测 |
| CT-06 | 批量导出 | 导出通讯录为 CSV |
| CT-07 | 分组/标签 | 可选，为客户打标签（如"VIP""新客户"），便于筛选发送 |

**客户数据模型：**

```
Customer {
  id          String    主键
  name        String    姓名（必填）
  salutation  String    称呼（必填，如"张总"）
  email       String    邮箱地址（必填，格式校验）
  tags        String[]  标签（可选）
  remark      String    备注（可选）
  createdAt   DateTime  创建时间
  updatedAt   DateTime  更新时间
}
```

### 2.3 邮件模板编辑

| 编号 | 功能 | 说明 |
|------|------|------|
| TM-01 | 可视化编辑器 | 富文本编辑器（支持加粗、斜体、列表、图片、链接等） |
| TM-02 | 称呼变量插入 | 邮件正文支持插入 `{{称呼}}` 占位符，发送时替换为客户的实际称呼 |
| TM-03 | 模板保存 | 将编辑好的邮件保存为模板，可复用 |
| TM-04 | 模板列表 | 查看、编辑、删除已保存模板 |
| TM-05 | 邮件主题 | 支持设置邮件主题，主题中也支持 `{{称呼}}` 变量 |
| TM-06 | 附件上传 | 可选，支持上传附件（单文件 ≤20MB，总计 ≤50MB） |
| TM-07 | 预览功能 | 选择客户后预览实际发送效果（称呼已替换） |

**模板数据模型：**

```
MailTemplate {
  id          String    主键
  name        String    模板名称（必填）
  subject     String    邮件主题（必填，支持 {{称呼}}）
  body        String    邮件正文 HTML（必填，支持 {{称呼}}））
  attachments String[]  附件路径（可选）
  createdAt   DateTime  创建时间
  updatedAt   DateTime  更新时间
}
```

### 2.4 邮件发送

| 编号 | 功能 | 说明 |
|------|------|------|
| SN-01 | 选择客户 | 从通讯录多选客户，支持按标签批量选择 |
| SN-02 | 编辑/选择模板 | 可选择已保存模板或新编辑内容 |
| SN-03 | 发送前预览 | 展示每封邮件的实际内容（称呼已替换），可取消勾选不想发送的客户 |
| SN-04 | 批量发送 | 点击发送后，逐封调用腾讯企业邮箱 SMTP 发送 |
| SN-05 | 发送进度 | 实时显示发送进度（已发送/总数）及每封状态 |
| SN-06 | 发送频率控制 | 可配置发送间隔（如每封间隔 2~5 秒），避免被风控 |
| SN-07 | 失败重试 | 单封发送失败自动重试 1~3 次，仍失败则标记为失败 |
| SN-08 | 发送取消 | 发送过程中可取消，已发送的不撤回，未发送的终止 |

**发送流程：**

```
选择/编辑模板 → 选择客户 → 预览确认 → 提交发送任务
                                        ↓
                              Redis 队列（List/Stream）
                                        ↓
                              消费者逐封发送（频率控制）
                                        ↓
                              更新发送状态 → 前端轮询/SSE 推送进度
```

> 使用 Redis 作为消息队列，发送任务异步执行，避免前端长时间等待；同时 Redis 缓存发送进度，支持断点恢复。

### 2.5 发送记录

| 编号 | 功能 | 说明 |
|------|------|------|
| RC-01 | 记录列表 | 分页展示，支持按日期/客户/状态筛选 |
| RC-02 | 记录详情 | 查看单封邮件的完整内容（含称呼替换后的正文） |
| RC-03 | 状态标记 | 每封邮件状态：待发送 / 发送中 / 已发送 / 发送失败 |
| RC-04 | 批次查看 | 同一次批量发送归为同一批次，可按批次查看 |
| RC-05 | 失败重发 | 对失败邮件可一键重发 |

**发送记录数据模型：**

```
MailRecord {
  id          String    主键
  batchId     String    批次ID（同一批发送共享）
  customerId  String    客户ID（关联 Customer）
  toEmail     String    收件人邮箱（冗余存储，客户信息变更不影响历史记录）
  salutation  String    实际使用的称呼（冗余存储）
  subject     String    实际邮件主题（已替换变量）
  body        String    实际邮件正文 HTML（已替换变量）
  attachments String[]  附件路径
  status      Enum      待发送/发送中/已发送/发送失败
  retryCount  Number    重试次数
  errorMsg    String    失败原因（可选）
  sentAt      DateTime  发送成功时间
  createdAt   DateTime  记录创建时间
}
```

### 2.6 系统配置

| 编号 | 功能 | 说明 |
|------|------|------|
| CF-01 | 邮箱账号配置 | 配置腾讯企业邮箱 SMTP 信息（主机、端口、账号、授权码），管理员操作 |
| CF-02 | 发送参数 | 配置默认发送间隔、重试次数、单次最大发送数（存 Redis 缓存，修改即时生效） |
| CF-03 | 发件人信息 | 配置默认发件人名称和签名 |

## 3. 非功能需求

| 编号 | 类别 | 要求 |
|------|------|------|
| NF-01 | 性能 | 单次批量发送支持 ≥500 封；页面加载 ≤2s |
| NF-02 | 安全 | 密码 bcrypt 加密存储；SMTP 授权码加密存储；操作日志审计 |
| NF-03 | 可用性 | 界面响应式，支持主流浏览器（Chrome/Edge/Firefox） |
| NF-04 | 可靠性 | 发送任务入 Redis 队列持久化，进程重启后未消费任务自动恢复；失败记录可重发
| NF-05 | 兼容性 | 邮件正文兼容主流邮件客户端（Outlook、QQ邮箱、Gmail 等） |

## 4. 技术方案建议

| 层级 | 建议选型 | 说明 |
|------|---------|------|
| 前端 | Vue 3 + Element Plus + 富文本编辑器（WangEditor / TinyMCE） | 响应式 SPA |
| 后端 | Java Spring Boot | RESTful API |
| 数据库 | MySQL | 持久化存储 |
| 缓存 & 消息队列 | Redis | 缓存会话/配置，邮件发送任务队列 |
| 邮件发送 | JavaMail (spring-boot-starter-mail) | 通过腾讯企业邮箱 SMTP |
| 部署 | Docker 或直接部署于当前百度云服务器 | 与 OpenClaw 共存 |

### 腾讯企业邮箱 SMTP 配置参考

```
主机：smtp.exmail.qq.com
端口：465（SSL）/ 587（TLS）
需开启授权码登录（非邮箱密码）
```

## 6. 数据关系

```
Customer 1──N MailRecord   （一个客户有多条发送记录）
MailTemplate 1──N MailRecord  （一个模板可用于多次发送，但记录冗余存储实际内容）
MailRecord N──1 Batch      （多条记录属于一个批次）

Redis 用途：
├── mail:queue          发送任务队列（List/Stream）
├── mail:progress:{batchId}  批次发送进度缓存（Hash）
├── config:smtp        SMTP 配置缓存
└── session:*          用户会话缓存
```

> 注：邮件记录冗余存储实际发送的称呼、主题和正文，确保客户信息或模板修改后，历史记录不受影响。

## 7. 后续可扩展方向

- **定时发送**：设定时间定时触发批量发送
- **邮件追踪**：记录打开率、点击率（需邮件追踪服务）
- **变量扩展**：除 `{{称呼}}` 外支持更多变量（`{{姓名}}`、`{{公司}}` 等）
- **多邮箱轮询**：配置多个发件邮箱轮换发送，提升发送上限
- **客户去重**：导入时自动识别并合并重复客户
